## 공식 지식과 분리하는 이유

공식 문서는 게임이 **어떻게 동작하는지**를 설명하고, 커뮤니티 공략은 특정 패치와 랭크 환경에서 **어떻게 판단하면 좋은지**를 제안한다. 후자는 실력대, 조합, 패치와 플레이 성향에 따라 달라질 수 있다.

따라서 커뮤니티 주장은 다음 세 단계 중 하나로 표시한다.

| 등급        | 판정 기준                                                     | 사용 방법                                   |
| ----------- | ------------------------------------------------------------- | ------------------------------------------- |
| `확인됨`    | 작성자가 붙인 제목·설명·챕터 또는 영상 내용에서 직접 확인     | 출처와 시점을 붙여 공략 요약으로 사용       |
| `종합`      | 둘 이상의 확인된 항목에서 반복되는 패턴을 ERMeta가 요약       | 해석임을 밝히고 분석 가설·체크리스트로 사용 |
| `검증 필요` | 제목·댓글만 확인했거나 패치 이후 지도·수치가 바뀔 가능성이 큼 | 현재 패치와 원본 영상을 확인하기 전 미사용  |

조회수, 좋아요 수와 작성자의 랭킹은 참고 정보일 뿐 주장의 정확성을 증명하지 않는다. 댓글의 반응도 공략의 효과를 검증하는 통계로 사용하지 않는다.

## 수집 단위

새 공략을 추가할 때 최소한 아래 필드를 남긴다.

```yaml
source:
  author: "작성자 또는 채널"
  url: "원본 URL"
  published_at: "YYYY-MM-DD 또는 확인 불가"
  collected_at: "YYYY-MM-DD"
context:
  patch_or_season: "영상에서 명시한 범위 또는 미상"
  mode: "랭크 스쿼드 등"
  audience: "뉴비, 특정 역할군, 고티어 등"
claim:
  topic: "운영, 시야, 교전, 실험체 등"
  summary: "원문을 길게 복제하지 않은 요약"
  evidence: "챕터, 설명, 영상 내용, 댓글 중 하나"
  status: "확인됨 | 종합 | 검증 필요"
review:
  patch_sensitive: true
  conflicts: []
  next_check: "재검증 조건"
```

## 반영 절차

1. 원본 URL, 작성자, 게시일과 수집일을 기록한다.
2. 영상이 명시한 시즌·패치·모드·대상 실력대를 찾는다.
3. 공략의 판단을 짧은 주장 단위로 나눈다.
4. 공식 규칙, 작성자의 경험칙, ERMeta의 종합을 서로 다른 문장으로 쓴다.
5. 지도 위치, 오브젝트 시간, 아이템·실험체 수치는 모두 `패치 의존`으로 둔다.
6. 여러 출처에서 같은 원칙이 반복되면 `종합` 항목으로 승격하되 원본 링크를 유지한다.
7. 반대 사례나 충돌하는 공략이 생기면 하나를 지우지 않고 조건 차이를 기록한다.

## 활용 원칙

- 통계에서 이상 징후를 발견했을 때 커뮤니티 공략을 **원인 후보**로 사용할 수는 있지만 인과관계로 단정하지 않는다.
- 조합 추천 문구에는 공략의 역할·거리·성장 가설을 붙일 수 있지만 실제 승률·표본과 교차 검증한다.
- 사용자 제보는 닉네임을 공개해도 되는지 확인하고, 개인정보와 비공개 대화는 저장하지 않는다.
- 원문 전체나 자막 전문을 복제하지 않고, 검색 가능한 요약과 원본의 해당 시점 링크만 남긴다.

## 출처 제외 목록

| 출처        | 처리                                             | 이유        |
| ----------- | ------------------------------------------------ | ----------- |
| 민식박 채널 | 검색 후보에서 제외하고 지식·인용에 사용하지 않음 | 사용자 요청 |

제외 출처가 검색 결과에 나타나도 조회수 비교, 대체 출처 선정이나 교차 검증 표본에 포함하지 않는다.
