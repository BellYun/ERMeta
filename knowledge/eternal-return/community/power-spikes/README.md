## 파워 스파이크의 정의

파워 스파이크는 특정 조건을 넘은 직후 짧은 구간에 교전 기대값이 유의미하게 높아지는 현상이다. 다음을 구분한다.

| 유형 | 트리거 예시 | 필요한 검증 |
| --- | --- | --- |
| 장비 완성 | 영웅 장비 세트 완성, 핵심 전설 장비 획득 | 획득 시각 전후 교전 성과 |
| 스킬 레벨 | 핵심 일반 스킬 또는 궁극기 레벨 | 레벨 구간별 성과와 표본 |
| 무기 숙련 | 무기 스킬 해금·강화 구간 | 현재 무기 스킬 규칙과 숙련도 |
| 전술 스킬 | 특정 강화 단계 도달 | 스킬 그룹·레벨별 성과 |
| 조합 완성 | 진입과 후속 딜, 제어 연계가 모두 준비 | 세 구성원의 준비 상태 |
| 공간·시간 | 오브젝트, 금지구역, 크로노스피어 전에 좋은 위치 선점 | 패치별 지도·페이즈 규칙 |
| 상대적 우위 | 적보다 한 단계 앞선 장비·레벨·인원 | 절대 수치보다 양 팀 격차 |

## 커뮤니티 자료에서 유지할 원칙

네브짱 영상의 제목에는 승률 상승 수치가 들어가지만, 조회수나 제목만으로 그 효과를 검증할 수 없다. 이 레이어에는 다음의 일반 원칙만 남긴다.

- 전설 장비 획득은 단순 제작 목록이 아니라 오브젝트, 크레딧, 남은 재료와 교전 위험을 함께 보는 운영 결정이다.
- 항상 같은 전설 장비를 강제하기보다 현재 가진 자원과 팀의 다음 행동을 기준으로 우선순위를 바꿀 필요가 있다.
- 아이템별 추천과 제작 경로는 게시 당시 패치의 주장이다. 12.0 레시피 개편 이후에는 현재 데이터로 다시 검증해야 한다.

공개 댓글에서 “남는 오브젝트 재료를 유연하게 처리하는 최신 전설 장비 공략이 필요하다”는 수요도 확인했지만, 이는 사용자 요구이지 성능 사실은 아니다.

## ERMeta가 지금 측정할 수 있는 것

수집기는 참가자별 최종 장비, 장비 등급, 전설 제작 여부, 특성, 전술 스킬 그룹·레벨·사용 횟수, 시작 루트, 스킬 레벨업 순서를 저장한다. 관련 구현은 [`collect/index.ts`](../../../../supabase/functions/collect/index.ts)에 있다.

현재 데이터만으로는 다음을 구별하기 어렵다.

- 전설 장비를 **언제** 획득했는지
- 획득 직후 교전에서 이득을 봤는지, 이미 이긴 팀이 장비를 더 얻었는지
- 중간 시점의 양 팀 장비·레벨·숙련도 격차
- 오브젝트를 직접 획득했는지, 키오스크·드론·상대 처치로 얻었는지

따라서 최종 장비와 승률의 상관을 “이 아이템이 승리를 만들었다”는 인과로 표현하면 안 된다. 승리 중인 팀이 더 많은 자원을 획득하는 역인과가 강하다.

## 초기 가설 목록

| 가설 | 상태 | 이유 |
| --- | --- | --- |
| 영웅 장비 완성 직후가 첫 공통 교전 창이다 | 검증 필요 | 루트 속도와 조합별 편차가 큼 |
| 핵심 전설 장비 획득은 교전 성능을 올린다 | 검증 필요 | 선택 편향과 역인과가 큼 |
| 전술 스킬 강화 시점은 조합의 진입·생존 창을 바꾼다 | 검증 필요 | 그룹·레벨별 데이터로 분리 가능 |
| 한 실험체의 스파이크가 팀 전체 스파이크와 같지는 않다 | 종합 | 후속 진입·딜·보호 준비가 다를 수 있음 |
| 오래된 루트별 완성 시점은 12.0에 그대로 적용되지 않는다 | 확인됨 | 공식 패치노트가 저장 루트 초기화와 레시피 개편을 명시 |

## 다음 데이터 확장

1. 이벤트 시각별 장비·레벨·숙련도 스냅샷을 수집할 수 있는지 공식 API를 재검토한다.
2. 불가능하면 리플레이 표본을 수동 라벨링해 후보 스파이크의 방향만 검증한다.
3. `patch + character + weapon + tier`를 고정하고, 전설 제작 여부의 조건부 성과를 비교한다.
4. 표본이 충분해도 인과 표현을 피하고 `동반됨`, `상관됨`으로 표기한다.
