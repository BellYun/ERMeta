## 자료에서 보존할 축

서로 다른 자료에서 반복적으로 확인할 수 있는 분석 질문은 다음과 같다.

1. `자리와 유효 사거리`: 접촉 전에 전열·중열·후열이 어떤 간격을 유지하는가?
2. `본교전 보류`: 포킹, 상대 진입, 목표 고립 등 원하는 조건이 생길 때까지 무엇을 기다리는가?
3. `교전 턴`: 지금 우리 팀이 먼저 스킬을 쓸 턴인가, 상대의 진입을 기다릴 턴인가?
4. `압박과 시선`: 첫 행동 담당이 누구의 이동과 시선을 제한하는가?
5. `1선 판단`: 전열이 적 후열을 쫓을지, 아군 후열로 들어온 위협을 막을지 언제 바꾸는가?
6. `종료 판단`: 첫 시도가 성공하지 않았을 때 계속 추격할지 대형과 쿨다운을 되돌릴지 어떻게 결정하는가?

위 여섯 축은 영상 제작자가 공통으로 제시한 고정 분류표가 아니라, 공개된 주제를 ERMeta의 조합 설명에 맞게 재구성한 종합이다.

## ERMeta 3층 출력 모델

| 레이어            | 반드시 답할 질문                                                      | 출력 규칙                                                                          |
| ----------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 1. 구도 설계      | 본교전을 열기 전에 어떤 거리·각·대형을 유지하며 무엇을 기다리는가?    | `포킹 우위 대기`, `진입 유도·받아치기`처럼 구도에 이름을 붙이고 유지 행동을 설명   |
| 2. 싸움 전환 조건 | 어떤 사건이 일어날 때 대치에서 실제 교전으로 전환하는가?              | 제어 적중, 체력 우위, 이동기 소진, 상대 진입, 목표 고립 등 관찰 가능한 조건을 명시 |
| 3. 실제 교전 순서 | 전환 뒤 누가 먼저 행동하고, 화력·보호를 어떻게 넘기며, 언제 끝내는가? | `첫 턴 → 화력·보호 전환 → 마무리·리셋`만 순서로 표시                               |

`포킹을 기다린다`는 단순히 포킹 스킬을 먼저 쓰라는 뜻이 아니다. ERMeta에서는 `최대 사거리에서 본교전을 보류하면서 체력 우위 또는 상대 이동기 소진을 기다린다`는 구도와, `우위가 생긴 뒤 제어 적중을 전환 신호로 삼는다`는 조건으로 나눠 기록한다.

기존 `준비 → 신호 → 첫 턴 → 연계 → 마무리`를 한 줄의 교전 순서로 표시하면 대치 행동도 실제 전투 행동처럼 보인다. 내부 정보는 유지하되 화면에서는 앞의 두 단계를 `구도 설계`로, 뒤의 세 단계를 `실제 교전 순서`로 분리한다.

| 구도 유형          | 유지할 상태                                   | 싸움 전환 조건                              | 전환 후 실행                          | 실패 시                          |
| ------------------ | --------------------------------------------- | ------------------------------------------- | ------------------------------------- | -------------------------------- |
| 선진입 통로 확보   | 첫 진입 뒤에도 후속 화력이 닿는 전후열 간격   | 제어 적중·상대 핵심 이탈기 소진             | 한 대상에 후속 진입과 화력 집중       | 첫 진입이 막히면 즉시 리셋       |
| 포킹 우위 대기     | 최대 사거리에서 본교전 보류                   | 체력 우위·이동기 소진 뒤 제어 적중          | 포착된 같은 대상 점사                 | 추격하지 않고 다음 견제 턴 준비  |
| 전후열 정면 대형   | 전열 뒤에 후열 사거리 유지                    | 전열이 첫 주요 스킬을 받거나 가까운 적 고정 | 후열이 가장 가까운 위협부터 처리      | 전후열이 벌어지면 합류           |
| 진입 유도·받아치기 | 보호 범위가 겹치는 간격                       | 상대가 진입기를 실제 사용                   | 이동을 먼저 끊고 노출된 대상에 전환   | 보호 범위로 복귀                 |
| 다각도 압박        | 서로 다른 각을 동시에 유지                    | 보호에서 벗어난 목표에 두 각이 함께 닿음    | 두 각과 주 화력을 같은 시간대에 연결  | 한 각이 늦으면 진입 취소         |
| 전열 교대 난전     | 생존기·제어기 사용 순서를 엇갈림              | 전열 접촉                                   | 담당을 교대하며 쿨다운 공백을 메움    | 자원과 대형이 깨지면 합류        |
| 합의 신호 대기     | 첫 제어만 사전 합의하고 나머지 주요 스킬 보존 | 합의한 제어 적중                            | 같은 대상에 주요 스킬을 순서대로 사용 | 첫 제어 실패 시 나머지 스킬 보존 |

## 데이터와 가설의 경계

- 조합 승률·평균 RP·게임 수는 누적 조합 DB 관찰값이다.
- 구도 유형, 전환 조건과 교전 순서는 실험체·무기의 역할, 전술 성향, 전열 위치와 유효 사거리를 결합한 휴리스틱이다.
- 현재 DB에는 실제 교전 시작 시각, 스킬 사용 순서, 포커싱 대상과 사망 원인이 없다.
- 따라서 구도와 실행 순서는 리플레이에서 검증된 고정 정답이 아니라, 대치 중 기다릴 조건과 교전 책임을 합의하기 위한 설명이다.
- 사용자 제보는 패치, 실험체·무기, 조합, 단계, 성공·실패 조건과 가능한 리플레이 근거를 함께 받아야 한다.

## 다음 검증

1. 사용자 리플레이 제보에서 첫 진입자, 첫 피격자, 첫 처치 대상과 리셋 여부를 표본화한다.
2. 같은 조합에서도 상대 조합과 지형에 따라 `첫 턴`과 `받아치기`가 바뀌는 사례를 분리한다.
3. 패치별 역할 태그를 버전 관리하고, 진입기·밀쳐내기·이탈기 변경 때 해당 타임라인을 재검수한다.
4. 실제 전투 이벤트를 수집하게 되면 휴리스틱 순서와 관찰 순서를 별도 필드로 표시한다.
