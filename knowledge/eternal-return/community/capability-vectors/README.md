## 왜 능력 벡터가 필요한가

조합의 세 자리를 `선제 견제·주 화력·마무리`처럼 미리 정하면 다음 경우를 설명하지 못한다.

- 3원딜에서 한 명이 피해 마무리보다 상대 진입과 투사체를 억제하는 경우
- 같은 포킹 실험체가 다른 조합에서는 주 화력이나 제어 연계를 맡는 경우
- 보호·지역 장악·받아치기를 동시에 제공하는 실험체
- 같은 캐릭터라도 무기에 따라 사거리·지속 화력·진입 기능이 바뀌는 경우

따라서 한 실험체가 수행할 수 있는 모든 기능에 상대 점수를 주고, 해당 조합이 필요로 하는 기능과 다른 두 팀원의 점수를 비교해 담당을 정한다.

## 공식 스킬 설명에서 추출하는 신호

생성기는 공식 스킬 문장을 제품 문구로 복사하지 않고 다음 구조 신호의 출현만 계산한다.

| 신호               | 대표적인 공식 문장 구조                | 조합 설명에서 보강하는 기능 |
| ------------------ | -------------------------------------- | --------------------------- |
| `hardControl`      | 기절·속박·공중에 띄움·밀어냄·도발      | 개시, 제어, 억제, 보호      |
| `softControl`      | 이동 속도 감소·둔화                    | 제어, 접근 억제             |
| `persistentZone`   | 유지되는 영역·지대·장치·벽·덫          | 공간 장악, 진입 억제        |
| `allyProtection`   | 아군 보호막·회복·피해 감소             | 보호                        |
| `projectileDenial` | 적 투사체 감속·제거·차단               | 원거리 조합의 진입 억제     |
| `mobility`         | 돌진·도약·순간 이동                    | 개시 가능성                 |
| `untargetable`     | 대상 지정 불가                         | 전열 생존 보조 신호         |
| `selfSustain`      | 자신의 회복·보호막                     | 전열 유지 보조 신호         |
| `repeatedPressure` | 재사용·주기 피해·기본 공격·쿨다운 감소 | 반복 압박 참고 신호         |
| `executePressure`  | 잃은 체력·처치 조건                    | 마무리 참고 신호            |
| `visionControl`    | 시야 확보·차단·은신                    | 압박과 지역 통제 참고 신호  |

키워드는 스킬의 실제 성능이나 정확한 수치를 증명하지 않는다. 특히 피해량, 안전한 유효 사거리, 쿨다운과 적중 난이도는 설명 문구만으로 비교할 수 없다. 자동 추출값은 `officialUtility`로 별도 보존하며, 같은 제어·억제·보호 신호가 충분히 반복될 때만 담당 판단에 직접 참여한다. 피해량과 사거리는 이 신호로 뒤집지 않는다.

## 최종 기능 점수

각 캐릭터·무기 프로필에는 다음 기능 점수가 함께 생성된다.

```text
교전 개시 · 후속 진입 · 전열 유지 · 주 화력 · 후속 화력 · 선제 견제
제어 연계 · 진입 억제 · 아군 보호 · 마무리
```

기능 점수는 다음 세 층을 합친다.

1. `역할`: 탱커, 전사, 암살자, 스킬 딜러, 원거리 딜러, 지원가
2. `편집 전술 지식`: 진입, 돌진, 포킹, 지속 화력, 폭딜, 보호, 지역 장악
3. `공식 스킬 구조 신호`: 제어, 유지 영역, 투사체 억제, 아군 보호 등

선제 견제 사거리는 공식 설명의 `지정한 방향` 같은 표현으로 추정하지 않는다. 근거리·중거리·장거리 역할을 기본값으로 사용하고, 차이가 명확하게 검수된 캐릭터·무기만 상대 사거리 보정을 둔다.

## 담당 배정 규칙

담당은 세 실험체의 기능 점수를 같은 조합 안에서 비교해 배정한다. 한 실험체를 하나의 직책으로 고정하지 않고 `주 담당 + 보조 기능`으로 표현한다. 단일 화력원이 억제 능력도 갖는 경우에는 주 화력을 다른 실험체에게 잘못 넘기지 않고 `주 화력 + 진입 억제`로 보존한다. 포킹 조합의 세 번째 주 담당은 다음처럼 기능에 따라 달라진다.

1. 유지 영역·투사체 차단·둔화가 강하면 `진입 억제`
2. 아군 보호 기능이 강하면 `아군 보호`
3. 단발 제어 연계가 강하면 `제어 연계`
4. 위 기능보다 제거 능력이 강할 때만 `마무리`

### 아야·이바·헨리 사례

- 이바: 검수된 상대 사거리와 포킹 기능으로 `선제 견제`
- 아야: 원거리 딜러 역할과 지속 화력으로 `주 화력`
- 헨리: 공식 스킬 설명에서 시간 제어 장치의 지속 둔화 영역, 궁극기의 투사체 감속·제거와 기절이 확인되어 `진입 억제`

이 배정은 헨리가 항상 억제만 맡는다는 뜻이 아니다. 아야·이바와 함께라면 `진입 억제 + 제어 연계`, 레녹스·요한과 함께라면 유일한 딜러이므로 `주 화력 + 진입 억제`가 된다. 다른 두 팀원의 기능에 따라 헨리의 포킹·제어·화력 점수를 다시 비교한다.

## 근거와 한계

- 공식 Open API 문서는 스킬 그룹 이름을 L10N 키로 해석하는 구조를 제공한다.
- [헨리 공식 소개](https://event.playeternalreturn.com/S8/Henry?hl=ko-KR)는 시간 제어 장치의 둔화·속박과 시간 재구축 영역의 투사체 억제·기절 구조를 설명한다.
- [9.3 공식 패치노트](https://playeternalreturn.com/posts/news/3163?hl=ko-KR)는 헨리를 지역 장악 능력이 뛰어난 실험체로 명시한다.
- 현재 데이터에는 실제 교전 중 스킬 적중, 포커싱 대상과 사망 원인이 없으므로 기능 점수는 승률로 검증된 인과 효과가 아니다.
- 비형과 크레이버는 현재 L10N 스냅샷에 스킬 설명이 없어 편집 지식으로만 생성하며, 다음 공식 데이터 갱신 때 재생성해야 한다.

## 사용자 제보 반영

사용자 교정은 `캐릭터의 고정 역할`이 아니라 다음 형태로 저장한다.

```yaml
composition_context:
  members: [아야, 이바, 헨리]
  observed_assignment:
    아야: 주 화력
    이바: 선제 견제
    헨리: 진입 억제
  reason:
    - 상대 유효 사거리 차이
    - 지속 영역과 투사체 억제
  status: user-confirmed-needs-replay-validation
```

같은 교정이 여러 조합에서 반복되면 캐릭터·무기 능력 벡터를 갱신하고, 특정 세 명에서만 성립하면 조합 문맥 사례로 보존한다.
