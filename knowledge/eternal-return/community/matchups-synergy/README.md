## 세 가지 질문을 분리한다

| 분석 단위 | 질문 | 필요한 비교 |
| --- | --- | --- |
| 2인 시너지 | A와 B가 함께할 때 A의 평소 성과보다 좋은가? | 같은 패치·티어·무기의 A 기준선 |
| 3인 조합 | A+B+C 팀이 실제로 얼마나 안정적인가? | 출전 수, 승률, 평균 RP·순위, 신뢰구간 |
| 적 상성 | 우리 조합이 특정 적 조합을 상대할 때 좋은가? | 양 팀 구성을 모두 조건으로 한 직접 대결 표본 |

2인 시너지가 높아도 세 번째 실험체가 필요한 기능을 채우지 못하면 좋은 3인 조합이 아닐 수 있다. 반대로 전체 승률이 높은 실험체와 함께한 것만으로 특정 두 실험체의 고유 시너지라고 단정할 수도 없다.

## 시너지 설명 축

통계 결과에 다음 기능 가설을 붙인다. 가설은 설명 후보이지 승률의 원인 확정이 아니다.

| 축 | 확인할 질문 |
| --- | --- |
| 진입 연결 | 선진입 뒤에 후속 제어·딜이 같은 시간 창에 들어오는가? |
| 사거리 정렬 | 세 명이 비슷한 거리에서 압박하는가, 한 명만 고립되는가? |
| 피해 창 정렬 | 순간 폭딜과 지속 딜의 타이밍이 목표 처치로 이어지는가? |
| 보호·받아치기 | 핵심 딜러를 지키거나 적 진입을 끊을 수 있는가? |
| 목표 접근 | 전열 처리와 후열 접근 중 필요한 경로가 있는가? |
| 자원 경쟁 | 핵심 전설 재료·포지션·안전한 딜 공간을 과도하게 공유하는가? |
| 성장 곡선 | 초·중·후반의 약한 구간이 세 명에게 동시에 오는가? |
| 실패 복구 | 첫 진입 실패 후 이탈·재진입·추격을 누가 담당하는가? |

## 상성 설명 축

적 상성은 캐릭터 이름 한 쌍보다 다음 조건으로 먼저 표현한다.

- 사거리 차이와 시야를 먼저 잡는 쪽
- 이동기·후열 접근 수단과 이를 끊는 제어
- 순간 폭딜을 버티는 생존 수단과 회복
- 채널링·긴 선후딜을 중단시키는 능력
- 좁은 길, 개방 지형, 벽과 수풀 등 지형 조건
- 양 팀의 현재 장비·레벨·숙련도와 핵심 스킬 준비 상태
- 크로노스피어 이동 방향과 재진입 가능 공간

따라서 “A가 B의 카운터”보다 “동일 성장 상태에서 A의 어떤 수단이 B의 어떤 승리 조건을 제한한다”는 문장을 우선한다.

## ERMeta 데이터의 현재 상태

### 3인 조합

수집기는 같은 `teamNumber`의 정확히 3명을 하나의 표본으로 만들고, 실험체 순서를 정규화한다. 조합 통계는 출전 수, 우승 수, 평균 순위와 평균 RP를 제공하며 추천 정렬에는 Bayesian RP와 Wilson lower bound를 사용한다.

현재 패치의 조합을 판단할 때는 이 3인 조합 통계를 우선한다.

### 역사적 2인 페어

[`001.json`](../../../../backend/src/modules/synergy-pairs/data/001.json)은 `10.x`, `DIAMOND+` 범위의 정적 예시 데이터다. 기준 실험체·무기 성과와 파트너 동반 시의 `rpLift`, `winRateLift`, 표본 수와 신뢰도 라벨을 담는다.

이 구조는 새 집계의 설계 참고로는 유용하지만 데이터 자체는 시즌 12 추천에 쓰지 않는다. 당시 신뢰도 기준도 `500+ high`, `200+ medium`인 편집 규칙이지 통계적 유의성 검정은 아니다.

### 직접 적 상성

경기 원본에는 참가자와 팀 정보가 있지만 현재 지식 레이어에서 사용할 수 있는 패치별 적 조합 대면 집계는 없다. 적 상성 표를 만들기 전 다음이 필요하다.

1. 한 경기의 우리 팀과 실제로 교전한 팀을 알 수 있는가를 확인한다.
2. 단순 동시 참가를 직접 대결로 오인하지 않는다.
3. 교전 로그가 없다면 최종 순위만으로 카운터 관계를 만들지 않는다.
4. 수동 리플레이 표본은 통계 집계와 별도 출처로 보관한다.

```yaml
interaction_hypothesis:
  kind: "pair_synergy | trio_synergy | enemy_matchup"
  patch: "12.0"
  tier: "DIAMOND_PLUS"
  subjects:
    - character: "A"
      weapon: "무기"
    - character: "B"
      weapon: "무기"
  condition: "동일 성장 상태, 특정 지형 등"
  mechanism: "진입 연결·사거리·보호 등 설명 가설"
  metrics:
    games: null
    win_rate: null
    average_rp: null
    average_rank: null
    baseline_delta: null
  confidence: "high | medium | low | unknown"
  evidence:
    status: "통계 확인 | 종합 | 검증 필요"
    sources: []
  reviewed_at: "YYYY-MM-DD"
```

## 제품 반영 기준

- 현재 패치가 다르면 추천 카드에 노출하지 않는다.
- 표본 수와 기준선 없이 `최고 시너지`, `카운터`라고 쓰지 않는다.
- 높은 동반 성과는 먼저 픽률, 파티 숙련도, 전체적으로 강한 파트너 효과를 의심한다.
- 공략의 역할 설명과 통계 방향이 일치하면 `가능한 이유`로만 붙인다.
- 사용자 제보는 패치·티어·무기·상대 조합·상황을 받은 뒤 `검증 필요`로 시작한다.
