# 이터널 리턴 도메인 지식 베이스

> ERMeta를 개발하거나 분석할 때 공통 전제로 사용할 이터널 리턴 지식 문서다. 게임 설명을 그대로 옮기는 대신, 공식 자료에서 확인한 사실과 ERMeta 내부 집계 규칙을 구분해 기록한다.

| 항목          | 값                                                                   |
| ------------- | -------------------------------------------------------------------- |
| 조사 기준일   | 2026-08-06 (KST)                                                     |
| 주 대상 모드  | 루미아 섬 일반/랭크 스쿼드                                           |
| 프로젝트 관점 | 캐릭터·무기·빌드·3인 조합·패치별 메타 분석                           |
| 우선 출처     | 공식 홈페이지 → 공식 고객센터/패치노트 → 공식 Open API → 저장소 코드 |
| 제외 범위     | 캐릭터별 공략, 커뮤니티 평가, 패치별 티어리스트처럼 빠르게 낡는 주장 |

빠르게 변하는 공략은 이 문서에 섞지 않고 [커뮤니티 지식 레이어](community/README.md)에 출처와 패치 맥락을 붙여 보관한다. 특성·전술 스킬·무기 스킬의 코드와 구조는 [시스템 사전](systems/traits-tactical-weapon-skills/README.md)에서 관리한다.

## 문서 읽는 법

이 문서는 다음 네 종류의 지식을 구분한다.

| 표기            | 의미                                                                     |
| --------------- | ------------------------------------------------------------------------ |
| **공식 사실**   | 님블뉴런의 홈페이지, 고객센터, 패치노트 또는 Open API 문서로 확인한 내용 |
| **ERMeta 규칙** | 이 저장소의 수집·집계·표시 코드가 정의한 동작                            |
| **분석 기준**   | ERMeta에서 통계를 해석할 때 지켜야 하는 원칙                             |
| **패치 의존**   | 특정 패치에서만 유효하며 현재 패치에서 다시 확인해야 하는 내용           |

패치 번호, 캐릭터 수, 아이템 수, 수치, 오브젝트 생성 시각은 이 문서만 믿고 사용하지 않는다. 런타임에서는 `PatchVersion`, 공식 패치노트와 Open API 데이터가 우선이다.

## 1. 게임을 한 문장으로 설명하면

이터널 리턴은 루미아 섬에서 재료를 탐색하고 장비를 제작하며, 야생 동물과 다른 팀을 상대해 마지막까지 생존하는 팀 기반 `Multiplayer Battle Survival Arena`다. 공식 일반/랭크 모드는 **3인 1팀, 8팀, 총 24명**으로 진행된다.

- 공식 홈페이지는 핵심 흐름을 `Search, Craft, Hunt, Fight`와 생존으로 설명한다.
- 일반 대전은 경험치와 A-Coin을 얻지만 RP는 얻지 않는다.
- 랭크 대전은 결과에 따라 RP를 얻거나 잃으며 티어를 올린다.
- 코발트 프로토콜은 파밍 중심의 루미아 섬 모드와 별개인 4대4 전투 모드이므로 통계를 섞으면 안 된다.

근거: [이터널 리턴 소개](https://playeternalreturn.com/about?hl=en-US), [공식 게임 모드 안내](https://support.playeternalreturn.com/hc/ko/articles/20412707019161)

## 2. 핵심 게임 구조

### 2.1 매치의 기본 단위

| 개념          | 도메인 의미                        | 데이터에서 주로 보는 값                        |
| ------------- | ---------------------------------- | ---------------------------------------------- |
| 실험체        | 플레이어가 조종하는 캐릭터         | `characterNum`, `characterCode`                |
| 무기군        | 실험체가 사용하는 무기 숙련 계열   | `bestWeapon`, `weaponType`                     |
| 플레이어 결과 | 한 매치에 참가한 한 명의 최종 기록 | 순위, 킬, 어시스트, 장비, RP 변화              |
| 팀            | 동일 `teamNumber`를 공유하는 3명   | 팀 순위와 3인 구성                             |
| 매치          | 하나의 `gameId`로 식별되는 경기    | 최대 24명의 결과 행                            |
| 패치          | 밸런스와 시스템 규칙의 버전 경계   | `versionMajor`, `versionMinor`, `patchVersion` |
| 시즌          | 랭크와 패치 번호의 상위 주기       | `seasonId`                                     |

공식 Open API의 `games/{gameId}`는 한 경기의 전체 플레이어 결과를 반환한다. 결과에는 캐릭터, 최종 순위, 킬/어시스트, 야생 동물 처치, 장비, 숙련도, 스킬 순서, 게임 버전 등이 포함된다. [BSER Open API 모델 문서](https://developer.eternalreturn.io/static/media/Docs_EN_20250220.pdf)

### 2.2 실험체와 무기군은 함께 봐야 한다

실험체만으로 성능을 묶으면 서로 다른 무기 운용이 하나로 합쳐질 수 있다. ERMeta의 기본 캐릭터 통계 키가 `(characterNum, bestWeapon, tier, patchVersion)`인 이유다.

주의할 점은 공식 API의 `bestWeapon`이 단순한 “로비에서 선택한 무기”가 아니라 **경기 종료 시 가장 높은 무기 숙련도의 ID**로 정의되어 있다는 것이다. 따라서 다중 무기 운용이나 특수한 전환형 실험체를 해석할 때는 실제 게임 규칙과 데이터 정규화 로직을 함께 확인해야 한다.

근거: [Open API의 Battle Game Results 정의](https://developer.eternalreturn.io/static/media/Docs_EN_20250220.pdf), [ERMeta v2 테이블](../../backend/migrations/001_v2_tables.sql)

### 2.3 전투력은 캐릭터 하나로 결정되지 않는다

메타 분석에서 최소한 다음 요소를 별도 축으로 취급한다.

- 실험체와 무기군
- 최종 장비 5부위와 전설·초월 장비 우선순위
- 핵심/보조 특성
- 전술 스킬과 강화 단계
- 스킬 레벨업 순서
- 시작 루트와 시작 지역
- 함께 플레이한 두 명의 실험체·무기·특성
- 패치, 티어 버킷, 표본 수

Open API는 장비, 특성, 전술 스킬, 스킬 순서, 시작 루트 등 여러 필드를 제공한다. 다만 API 모델은 계속 바뀔 수 있으므로 구현할 때는 현재 개발자 포털의 최신 모델과 실제 응답을 다시 확인한다.

실험체의 조작·판단 부담과 숙련 곡선은 API가 직접 제공하지 않는 별도 파생 특성이다. 커뮤니티 자료에서 수집한 가설은 공식 데이터와 분리해 [실험체 특성·숙련 난이도 지식](community/characters/README.md)에 기록한다.

### 2.4 파밍과 성장

루미아 섬의 기본 흐름은 재료 탐색, 장비 제작, 야생 동물/오브젝트 사냥, 적 팀과의 전투다. 저장된 루트는 목표 장비, 특성, 전술 스킬, 이동 경로와 스킬 순서를 담을 수 있다.

크레딧은 시간 경과, 야생 동물, 실험체, 현상금과 주요 오브젝트 등으로 얻을 수 있다. 원격 드론으로 재료를 주문하거나 키오스크에서 특수 재료를 구매하고, 팀원을 부활시키거나 탈출용 아이템을 마련하는 데도 쓰인다.

근거: [공식 크레딧·키오스크 안내](https://support.playeternalreturn.com/hc/ko/articles/20584542119321), [Open API의 Saved Plan 모델](https://developer.eternalreturn.io/static/media/Docs_EN_20250220.pdf)

### 2.5 공간과 시간도 메타의 일부다

루미아 섬은 지역, 낮/밤 페이즈, 금지구역과 최종 안전지대에 따라 이동과 교전이 강제된다. 오브젝트, 야생 동물, 특수 지형과 지역 기믹도 패치로 바뀐다. 따라서 다음 주장은 캐릭터 수치만으로 설명하면 안 된다.

- 특정 시작 루트의 성과 변화
- 특정 조합의 초반 안정성 또는 후반 생존력
- 패치 이후 픽률 급변
- 전설 장비 완성 시점과 평균 RP 변화

예를 들어 시즌 11의 11.0 패치는 신규 지역과 지역 기믹을 추가하고, 함정 아이템을 제거해 캡슐 소비 아이템으로 대체했으며, 후반 안전지대 페이즈도 조정했다. 이는 “캐릭터 수치가 바뀌지 않아도 메타가 바뀔 수 있다”는 사례다.

근거: [11.0 패치노트](https://playeternalreturn.com/posts/news/3530?hl=en-US)

## 3. 모드와 랭크

### 3.1 통계를 섞으면 안 되는 모드

| 모드                | 기본 구조                                 | ERMeta 기본 분석 포함 여부 |
| ------------------- | ----------------------------------------- | -------------------------- |
| 랭크 스쿼드         | 3인 1팀, 24명, RP 증감                    | 포함                       |
| 일반 스쿼드         | 3인 1팀, 24명, RP 없음                    | 기본 수집에서는 제외       |
| 코발트 프로토콜     | 4대4, 별도 장비·인퓨전·라이프 포인트 규칙 | 제외                       |
| 연습/AI/사용자 설정 | 학습 또는 사용자 정의 경기                | 제외                       |
| 이벤트 모드         | 기간과 규칙이 한정됨                      | 별도 명시 없이는 제외      |

**ERMeta 규칙:** 현재 수집기는 `matchingMode === 3`인 랭크 경기만 받는다. [수집 코드](../../supabase/functions/collect/index.ts)

### 3.2 공식 티어와 ERMeta 버킷은 다른 개념이다

공식 고객센터가 안내하는 랭크 티어는 아이언, 브론즈, 실버, 골드, 플래티넘, 다이아몬드, 메테오라이트, 미스릴, 데미갓, 이터니티의 10단계다. [공식 랭크 티어 안내](https://support.playeternalreturn.com/hc/ko/articles/4403870835609)

ERMeta의 `PLATINUM`, `DIAMOND`, `METEORITE`, `MITHRIL`은 공식 표시 티어를 그대로 저장한 값이 아니라 `mmrBefore` 임계값으로 나눈 **서비스 내부 분석 버킷**이다.

| ERMeta 버킷     |  현재 코드의 MMR 범위 | 비고                                                  |
| --------------- | --------------------: | ----------------------------------------------------- |
| `DIAMOND_BELOW` |            3,600 미만 | 수집 제외                                             |
| `PLATINUM`      | 3,600 이상 5,000 미만 | 수집 대상                                             |
| `DIAMOND`       | 5,000 이상 6,400 미만 | 수집 대상                                             |
| `METEORITE`     | 6,400 이상 7,600 미만 | 수집 대상                                             |
| `MITHRIL`       |            7,600 이상 | 수집 대상                                             |
| `IN1000`        |      현재 임계값 없음 | enum/일부 조회 코드에는 남아 있지만 수집에서는 제거됨 |

이 값들은 공식 티어 경계라고 표시하면 안 된다. 시즌이나 서비스 정책에 따라 바뀔 수 있는 ERMeta 내부 분류다. 단일 버킷과 `DIAMOND_PLUS` 같은 누적 조회도 구분해야 한다.

근거: [티어 분류 코드](../../supabase/functions/_shared/tier-utils.ts), [누적 티어 조회 코드](../../backend/src/modules/meta/meta.service.ts)

## 4. 패치와 시즌

2025년 시즌 8부터 공식 버전 표기는 `시즌 번호.주요 업데이트 번호` 형태로 바뀌었다.

- `8.0`: 시즌 8 프리시즌
- `8.1`: 시즌 8 랭크 시작
- `8.4`: 시즌 중반 업데이트
- `9.0`: 시즌 9 프리시즌

따라서 `11.6`은 단순한 소수점 숫자가 아니라 “시즌 11의 여섯 번째 주요 업데이트”라는 식으로 해석해야 한다. 버전 문자열을 부동소수점으로 변환하거나 `11.10 < 11.9`처럼 사전식/숫자식 정렬을 혼용하면 안 된다.

근거: [8.0 패치노트의 버전 규칙 변경](https://playeternalreturn.com/posts/news/2827?hl=en-US)

### ERMeta의 패치 판정

**ERMeta 규칙:** 수집기는 우선 게임 응답의 패치 버전을 사용하고, 없으면 경기 시작 시각을 `PatchVersion.startDate/endDate` 구간에 대입한다. 종료일이 비어 있는 과거 패치도 다음 패치 시작일로 닫아 활성 패치로 잘못 분류하지 않도록 한다.

또한 프리시즌이나 데이터 품질 문제로 특정 패치를 통계에서 제외할 수 있다. 현재 메타 서비스에는 `11.0` 제외 규칙이 있다. 이 규칙은 게임의 보편적 사실이 아니라 ERMeta 제품 정책이다.

근거: [패치 판정 수집 코드](../../supabase/functions/collect/index.ts), [메타 서비스](../../backend/src/modules/meta/meta.service.ts)

## 5. ERMeta 데이터가 의미하는 것

### 5.1 수집 대상과 원본 단위

현재 수집 파이프라인은 다음 순서로 데이터를 만든다.

1. 랭크 경기만 선택한다.
2. 경기 시작 시각과 패치 구간으로 `patchVersion`을 확정한다.
3. 참가자의 경기 전 MMR로 ERMeta 티어 버킷을 정한다.
4. 참가자 한 명을 캐릭터·무기·빌드 통계에 누적한다.
5. 같은 `teamNumber`에 정확히 3명이 있는 팀만 3인 조합으로 만든다.
6. 조합원 세 명이 공통으로 속한 분석 버킷이 있을 때만 조합 통계에 누적한다.
7. 조합원은 `characterNum` 순으로 정렬해 같은 조합의 순서 차이를 제거한다.

**분석 기준:** 수집된 표본은 전체 유저의 무작위 표본이 아니다. 현재 MMR 기준을 통과한 랭크 참가자 표본이므로 “전체 이용자 메타”가 아니라 “ERMeta 수집 조건 내 메타”라고 해석해야 한다.

### 5.2 캐릭터 통계

`v2_CharacterStats` 한 행의 기준은 캐릭터·무기·티어 버킷·패치다.

| 저장값        | 의미                                   |
| ------------- | -------------------------------------- |
| `totalGames`  | 해당 캐릭터·무기 조건의 참가자 출전 수 |
| `totalWins`   | `gameRank = 1`인 출전 수               |
| `totalTop3`   | `gameRank <= 3`인 출전 수              |
| `totalRP`     | 각 출전의 `mmrAfter - mmrBefore` 합    |
| `averageRank` | 출전별 최종 팀 순위의 평균             |

주요 파생 지표는 다음과 같다.

```text
승률      = totalWins / totalGames × 100
Top3 비율 = totalTop3 / totalGames × 100
평균 RP   = totalRP / totalGames
픽률      = 해당 캐릭터·무기 totalGames / 같은 조회 집합의 전체 totalGames × 100
```

여기서 픽률은 공식 API가 직접 주는 값이 아니라 ERMeta가 **현재 조회 집합에서 차지하는 출전 비중**으로 계산한 값이다. 어떤 티어를 합쳤는지, 무기별 행을 합쳤는지에 따라 분모가 달라진다.

근거: [집계 RPC](../../backend/migrations/009_bulk_collect_optimization.sql), [메타 계산 코드](../../backend/src/modules/meta/meta.service.ts)

### 5.3 3인 조합 통계

3인 조합은 플레이어 행이 아니라 **팀 한 개**가 표본 단위다.

- 조합의 캐릭터 순서는 의미가 없으므로 canonical order로 저장한다.
- 무기를 포함한 조합은 `(캐릭터, 무기, 핵심 특성)` 세 쌍을 함께 봐야 한다.
- `totalGames`는 해당 조합으로 출전한 팀 수다.
- `totalWins`는 그중 1위 팀 수다.
- `averageRank`는 팀 최종 순위 평균이다.
- 팀 RP는 세 팀원의 경기 전후 MMR 변화 평균을 기반으로 수집한다.

단순 승률 정렬은 소표본 100% 승률 조합을 과대평가한다. ERMeta의 추천 정렬은 Bayesian RP, Wilson lower bound와 평균 순위를 섞어 이런 문제를 완화한다. 이것은 공식 게임 점수가 아니라 ERMeta의 추천 휴리스틱이다.

역할 구성, 딜 기여와 점사 구도를 해석하는 커뮤니티 가설은 공식·집계 규칙과 분리해 [3인 조합 커뮤니티 지식](community/composition/README.md)에 기록한다.

근거: [조합 파싱](../../supabase/functions/collect/index.ts), [추천 점수 코드](../../backend/src/modules/stats/stats.service.ts)

## 6. 지표 해석 규칙

### 6.1 승률만으로 강함을 판단하지 않는다

3인 8팀 경기에서 모든 팀의 우승 가능성이 같다는 단순 기준의 1위 확률은 12.5%다. 이는 설명을 위한 수학적 기준일 뿐, 캐릭터별 밸런스 목표나 공식 기준은 아니다.

승률은 최소한 다음과 함께 읽는다.

- 픽률: 소수 숙련자만 사용하는지, 널리 사용되는지
- 평균 RP: 1위뿐 아니라 전체 랭크 성과가 어땠는지
- 평균 순위와 Top3 비율: 우승 전환과 생존 안정성의 차이
- 표본 수: 우연 변동 가능성
- 이전 패치 대비 변화: 절대값과 변화 방향
- 무기군과 조합: 같은 실험체라도 운용 맥락이 다른지

### 6.2 패치 비교는 같은 조건끼리 한다

유효한 비교의 최소 키는 다음과 같다.

```text
mode + patchVersion + tier definition + character + weapon
```

조합 분석이라면 팀 구성과 각 무기/핵심 특성까지 포함한다. 티어 버킷 경계나 수집 방식이 바뀌었다면 패치가 달라도 그대로 비교할 수 없다.

### 6.3 변화량의 단위를 명시한다

- 승률 `12% → 13%`는 `+1%` 증가가 아니라 보통 **+1%p**로 쓴다.
- 상대 변화율이 필요하면 `(현재 - 이전) / 이전 × 100`을 별도로 표시한다.
- RP는 포인트 단위, 순위는 낮을수록 좋다는 방향을 명시한다.
- 픽률 분모가 캐릭터 전체인지 캐릭터·무기 전체인지 적는다.

### 6.4 상관관계를 인과관계로 쓰지 않는다

“A와 B 조합의 승률이 높다”는 결과만으로 “B가 A의 약점을 보완해서 높다”고 단정하지 않는다. 다음 대안 설명이 존재한다.

- 표본이 적다.
- 특정 고숙련 팀이 반복 사용했다.
- 세 번째 팀원이 실제 성과를 만들었다.
- 같은 시간대·서버·MMR 집단에 표본이 몰렸다.
- 패치 초반 탐색 편향이 있다.
- 강한 아이템/루트 선택이 조합 효과처럼 보인다.

원인을 설명하려면 역할군, 딜 구조, 교전 거리, 군중 제어, 성장 곡선 같은 별도 근거가 필요하다.

## 7. 공식 Open API와 ERMeta의 관계

공식 Open API 문서에서 ERMeta와 직접 연결되는 모델은 다음과 같다.

| API 영역             | 용도                            | 주의점                                        |
| -------------------- | ------------------------------- | --------------------------------------------- |
| 닉네임 → 사용자 번호 | 멀티서치 시작점                 | 닉네임은 변할 수 있고 사용자 번호가 식별자    |
| 시즌 상위 랭커       | 수집 대상 탐색                  | 시즌·팀 모드·서버 구분 확인 필요              |
| 사용자 시즌 통계     | 개인 랭크/캐릭터 요약           | 서비스 집계 정의와 API 정의가 다를 수 있음    |
| 사용자 최근 경기     | 사용자의 경기 ID 탐색           | 공개 문서 스냅샷에는 최근 90일로 설명됨       |
| 경기 결과            | 한 `gameId`의 전체 참가자 기록  | 캐릭터·장비·순위·RP·숙련 등 핵심 원본         |
| 게임 데이터 테이블   | 캐릭터/아이템 등의 메타데이터   | hash와 테이블 버전으로 변경 감지 필요         |
| 다국어 데이터        | 코드 → 한국어/영어/일본어 명칭  | 번역 리소스 갱신 시점 확인 필요               |
| 추천 루트            | 저장된 목표 장비·특성·스킬·경로 | 사용자 생성 데이터이므로 품질이 균일하지 않음 |

공식 API PDF는 날짜가 붙은 모델 스냅샷이다. 엔드포인트나 필드가 최신이라고 가정하지 말고 [개발자 포털](https://developer.eternalreturn.io/)과 실제 응답을 함께 확인한다.

## 10. 유지보수 규칙

1. 수치나 현재 상태를 추가할 때는 패치 번호와 확인일을 함께 적는다.
2. 공식 자료가 있으면 커뮤니티 위키나 게시글보다 우선한다.
3. 공식 사실, ERMeta 구현, 분석상 추론을 한 문장 안에서 섞지 않는다.
4. 코드가 바뀌면 관련된 “ERMeta 규칙”도 같은 PR에서 갱신한다.
5. 현재 패치 번호는 이 문서에 상수처럼 고정하지 않는다.
6. 역할·시너지처럼 공식 정답이 없는 분류는 근거와 분류 버전을 남긴다.
7. 출처가 사라지거나 오래되면 삭제하지 말고 `검증 필요`로 표시한 뒤 대체 출처를 찾는다.
